# Project

Python ≥3.9, `src/` layout, managed with `uv`. Packages in `src/`: `registry` (generic
config→class registry), `repos` (file repositories + path generators), `racker`.
Tests mirror `src/` under `test/`. Root `tmp/` is scratch/legacy code, not part of the package.

# Commands

- Tests: `uv run pytest test` (single file: `uv run pytest test/registry/test_registry.py`)
- Lint: `uv run ruff check src test` · format: `uv run ruff format src test`
- Types: `uv run mypy src` (strict mode)
- Container: `./stack build | up | down | exec`

Run tests, ruff and mypy after every change; all must pass.

# Code style

- Names are verbose and descriptive (`config_class`, not `cc`). No single-letter names
  except generic `TypeVar`s.
- Every variable, parameter and return value has a type annotation (mypy strict).
- No complex `if` conditions: compute the condition into a descriptively named variable first.

  ```python
  # Bad
  if path.exists() and not overwrite and path.stat().st_size > 0:
  # Good
  must_keep_existing_file: bool = path.exists() and not overwrite and path.stat().st_size > 0
  if must_keep_existing_file:

  # Good
  class Foo:
    def is_foo(): ...

    def check():
        if self.is_foo(): ...
  ```

- Line length 100. Docstrings on public classes and methods.

# Tests

- Use `pytest` with fixtures; typed and descriptively named like production code.
- Configuration objects are pydantic-validatable types (`BaseModel`, dataclasses).
- Static input files go in `test/fixtures/` (`FIXTURES_DIR` from `test/config.py`).
- Files generated by tests go under `TMP_DIR` (`test/config.py`) and must be deleted when
  the test finishes — create them in a `yield` fixture and remove them in its teardown.

# Documentation
- Test are documented in one-liners
- Documentation follows google style: Args and REturns minimum. Exceptions raised also documented
- No inline coments, except if code is complex to understand.
